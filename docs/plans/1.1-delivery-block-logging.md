## 1. Problem Statement

Independent delivery drivers currently lack a unified, offline-capable interface to log their exact shift metrics, such as mileage and fuel costs. Without a quick logging method, calculating annual write-offs becomes disorganized and prone to manual error. Delivering this specific feature provides the essential data entry point for the entire application, enabling drivers to track their business expenses reliably.

## 2. Goals

- Provide an Astro-based frontend UI for logging shift data.
- Capture inputs for miles driven, gas used, and pay.
- Save logged metrics as document-based records in MongoDB using a Node.js/Express backend.
- Ensure offline submission capability via Service Workers.

## 3. Non-Goals

- **Handling expired JWTs during offline sync:** If a user's token expires while they are in a cellular dead zone, the application will not automatically handle the re-authentication and resume the queue. This edge case is deferred to a future update.
- Implementing automated mileage tracking via the Google Maps API (deferred to future improvements).
- Building OCR capabilities to scan physical gas receipts.
- Developing dashboard data visualizations or reporting tools, strictly keeping the scope to a one-week MVP.

## 4. Personas & User Stories

- **As an independent Amazon Flex delivery driver**, I want to manually enter my block payout, the gas cost for my vehicle, and the exact mileage driven so that I can accurately aggregate data for tax write-offs.

## 5. Functional Requirements

- **FR-1.** The system MUST provide a user interface form to input `milesDriven` (number), `gasUsed` (number), and `pay` (number).
- **FR-2.** The system MUST transmit the entered data to the `POST /api/blocks` API route.
- **FR-3.** The system MUST associate the logged block data with the currently authenticated user's session.
- **FR-4.** The system SHOULD queue the form payload via Service Workers if the device loses cellular network connection.

## 6. Non-Functional Requirements

- **Performance** — The Astro frontend MUST render quickly and maintain lightweight PWA characteristics for mobile use.
- **Security** — API routes MUST validate the user's JWT to authorize block creation.
- **Privacy & Compliance** — N/A. No specific compliance regimens apply to this standard personal logging application.
- **Accessibility** — Form inputs MUST include appropriate label tags and WCAG 2.1 AA compliant contrast for outdoor readability.
- **Scalability** — N/A. Given the one-week timeline and MVP scope, advanced partitioning and load balancing strategies are deferred.
- **Reliability** — The Service Worker sync mechanism MUST gracefully handle rapid network toggling to prevent duplicate entries.
- **Observability** — N/A. Advanced telemetry and tracing are excluded from this 1-week MVP scope.
- **Maintainability** — Development MUST follow the weekly sprint cycle agile workflow, utilizing Git feature branches and pull requests.
- **Internationalization** — N/A. Fixed to US locales (USD currency, miles) for the initial release.
- **Backward compatibility** — N/A. This is a net-new feature with no previous data schemas to support.

## 7. Acceptance Criteria

- **AC-1.** *Given* an authenticated user on the block logging view, *When* they enter valid numerical values for miles, gas, and pay and click submit, *Then* a new block document is stored in the database and a success state is rendered.
- **AC-2.** *Given* an offline mobile device in a cellular dead zone, *When* the user submits a block log, *Then* the Service Worker caches the POST request and pushes it to `/api/blocks` automatically upon network restoration.
- **AC-3.** *Given* a form submission with negative or missing numbers, *When* the user attempts to submit, *Then* the UI blocks the submission and displays validation errors.
- **AC-4.** *Given* an invalid or missing JWT, *When* the frontend attempts to POST to `/api/blocks`, *Then* the server responds with a `401 Unauthorized` error.

## 8. Data Model

- **New Collection:** `blocks`
- **Fields & Constraints:** 
  - `_id` (ObjectId)
  - `userId` (String/ObjectId reference to User)
  - `milesDriven` (Number, min: 0)
  - `gasUsed` (Number, min: 0)
  - `pay` (Number, min: 0)
  - `dateLogged` (Date, defaults to `Date.now()`)
- **Indexes:** Create an index on `userId` to efficiently fetch a specific driver's blocks.
- **Backfill Strategy:** N/A. No existing records require backfilling.

## 9. API Surface

- **Route:** `POST /api/blocks`
- **Request Shape:** 
  ```json
  {
    "milesDriven": 45.5,
    "gasUsed": 10.50,
    "pay": 72.00
  }
  ```
- **Response Shapes:** 
  - **Success (201 Created):** Returns the inserted document body.
  - **Failure (400 Bad Request):** Returns `{"error": "Validation failed: milesDriven must be a positive number"}`.
  - **Failure (401 Unauthorized):** Returns `{"error": "Invalid or expired token"}`.
- **Authentication:** Requires a valid JWT in the Authorization header.

## 10. UI / UX

- **New Page:** `/log-block` (Astro frontend styled with Tailwind CSS).
- **Key Flows:** 
  1. Navigate to the `/log-block` path. 
  2. Fill numeric inputs for miles, gas, and pay. 
  3. Tap the "Save" button.
- **Mobile / responsive:** Must adapt perfectly to mobile screens as drivers will primarily use the tool in their vehicles.
- **Empty / loading / error states:** Form inputs clear upon successful submission. A visual indicator (toast notification) displays if the app is offline and the save is queued.

## 13. Dependencies & Sequencing

## 14. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Service Worker offline sync creating duplicate database entries due to rapid network toggling. | High | Medium | Implement a client-side UUID generation for each form submission to act as an idempotency key on the Express backend. |
| **Scope creep:** Service Worker Background Sync proves too complex to stabilize within a 1-week sprint. | Medium | High | **Fallback Plan:** Downgrade to standard `localStorage` caching with a manual "Sync Offline Logs" button on the UI to guarantee delivery by Friday. |
